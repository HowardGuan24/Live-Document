# ControlNet 线稿对照实验

## 结论

### 总结

“缺少有效线稿”确实是旧结果差的原因之一，但准确说是缺少“来自一幅视觉上已经成立的目标构图的真实可见边缘”，不是单纯缺少更多线。去掉 smooth_base img2img 后，稀疏 Canny 组的自然纹理明显优于旧 Route B；给合成语义线图时，模型忠实生成地图式沟槽；给自然参考图提取的 Canny 时，四张又全部恢复自然航拍质感。ControlNet 和本地模型能够做出网上 demo 那类自然重绘，当前瓶颈主要是控制图内容不成立。12 张候选仍没有一张满足最终目标，因为唯一几何正确的机制图太粗，而自然参考图本身又是错误的斜视狭长水道。

- 稀疏 Canny：四张都有比旧 Route B 更自然的沙地、水体和岸边纹理，证明纯 SDXL Canny 管线本身能生成细节；但 1734 个边缘像素只描述了一条笔直海岸和矩形河口，约束不足，模型仍按自身先验自由补成沙洲、狭长水道或斜岸，且没有可靠生成赭色水下羽流。
- 详细线图：四张都明显遵循新增线条，25352 个边缘像素不是被模型忽略了；问题是模型把五条羽流流线当成五条硬水道，把水深线和陆地等高线当成可见地貌分界，结果更像地图或沟渠系统，画面结构虽然更受控，照片真实性反而下降。
- 参考图实边 Canny：四张都保持了自然水岸、沙地和水体材质，没有详细线图组的网格与沟槽感。s3103 最接近源图，但源图本身也是 seed 3103，存在同 seed 先验重合，不能单独作为证据；不同 seed 的 s3101、s3102、s3104 也仍呈现自然航拍质感，并受源图强岸线锚定，但硬边之间的具体水域形状会漂移。它们证明这套 ControlNet 能使用自然图像边缘，却不能把错误参考构图自动改成目标河口。
- 根因判断：旧 Route B 有两个不同问题：smooth_base img2img 把低频大色块直接带进输出；稀疏 Canny 又没有提供足够的自然几何。本轮移除前者后画质恢复，换成自然参考实边后自然性进一步稳定。合成语义线不等于照片边缘。Canny 适合锁定可见的岸线、河岸和物体轮廓，不适合表示没有硬边界的悬浮泥沙密度。

### 盲评与逐组复核

先查看隐藏路线和 seed 的 comparison-blind.jpg，再打开 blind_order.json 解盲。盲看时，Candidate 02/07/09/11 都有自然水岸和连续材质；Candidate 01/03/06/12 都有明显网格、沟槽、平行边界或多水道；Candidate 04/05/08/10 较自然但几何约束弱。解盲后三组分别完整对应 reference_canny、detailed_lineart 和 sparse_canny，说明结论不是看标签后倒推。

- seed 3101：稀疏图生成了自然纹理但河口关系错误；详细图出现大量规则分区；参考实边图生成自然的弯曲岸带，但仍不是目标河口。
- seed 3102：稀疏图最接近“左侧河流进入右侧水体”，但像人工直渠且没有赭色羽流；详细图把五条流线变成多条蓝色水道；参考实边图形成自然但错误的汇流水岸。
- seed 3103：稀疏图退化为狭长纵向水带；详细图形成地图式平行线；参考实边图几乎重建自然源图，但同 seed 重合使这一张只能作直观展示，不能单独证明 ControlNet 贡献。
- seed 3104：稀疏图是自然海岸局部但看不出目标河流；详细图形成台地和硬分叉；参考实边图保留自然弯曲水岸，且它与源图 seed 不同。

- 稀疏组相对最好：`sparse_canny_s3102.png`，但不合格。
- 详细组相对最好：`detailed_lineart_s3102.png`，但不合格。
- 参考边缘组代表图：`reference_canny_s3104.png`，用于验证还原能力，不是目标构图。

### 这次实验能证明什么、不能证明什么

本实验能证明当前本地 SDXL Canny ControlNet 会响应控制线，也能证明旧 smooth_base 和稀疏机制边缘共同限制了结果。自然参考实边组证明，换成来自成立画面的边缘后，同一模型与 prompt 能恢复自然质感；但源图不是目标构图，因此不能证明我们已经有可用于最终画面的线稿。实验也没有测试 SoftEdge、Depth、Segmentation、IP-Adapter 或局部重绘。

### 下一步

先制作一张本身就视觉成立的粗参考构图：严格俯视、左侧单河道、自然海岸、开阔海域，随后只从其中真实可见的河岸和海岸提取 Canny；不要把等高线、水深线或羽流内部流线送给 Canny。ControlNet 只负责硬几何，赭色悬沙应作为软密度/颜色现象，用真实泥沙羽流参考图、SoftEdge/分割条件，或在锁定岸线后进行一次有明确记录的局部重绘。下一次仍应保留纯 ControlNet、相同 seed 的单变量对照。

## 1. 这个实验回答什么

旧 Route B 同时使用了 `smooth_base` img2img 和 Canny，因此无法区分结果差是因为平滑
底图，还是因为控制线条太少。本实验移除 img2img，只运行
`StableDiffusionXLControlNetPipeline`，并且只改变控制图：

- A：原来的 `sparse_canny.png`；
- B：新生成的 `detailed_lineart.png`；
- C：从已有自然航拍图逐像素执行 Canny 得到的 `reference_canny.png`。

模型、prompt、negative prompt、四个 seed、分辨率、步数、CFG 和 ControlNet scale
全部相同。没有 strength，因为本实验没有 img2img 初始图；没有 mask projection。
其中 C 最接近网上“从已有图像提取线条再重绘”的 demo，但它的源图不是合格目标构图，
所以只检验 ControlNet 能否利用真实图像边缘，不参与最终地理构图优选。

## 3. 为什么网上的 Canny demo 看起来更好

典型 Canny demo 的控制图通常来自一张已经有合理构图、透视、轮廓和物体比例的参考图。
Canny 只删除颜色和纹理，却保留了这些真实可见边缘；扩散模型的工作主要是把纹理和
风格重新填回去。

本实验的 A 来自 96×64 机制图，只有笔直海岸和矩形河道，缺少足够几何信息。B 虽然
线更多，却加入了地图式等高线、水深线和羽流内部流线。Canny ControlNet 不知道哪条线
是“仅供理解的说明”，会把它们都当成应该出现在成图里的强边界，于是生成沟槽、额外
水道和地质分界。悬浮泥沙本来是软密度场，也没有适合用 Canny 表达的硬轮廓。

所以真正的差别不是简单的“有没有线稿”，而是控制图是否来自一幅视觉上已经成立的
目标构图，以及其中每条边是否应该成为成图的可见边缘。C 组就是对此判断的直接检查。
