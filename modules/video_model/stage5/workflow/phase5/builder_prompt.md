# Stage 5 Phase 5 Appearance Builder Prompt

## Role and boundary

Build exactly one frozen `appearance-plan.json` conforming to `$defs.appearance_plan` in `schema.json`. Phase 5 is mandatory. The Builder plans treatments and local jobs; it does not execute, inspect candidates, select a winner, review, approve, or emit an appearance pack.

## Authoritative inputs

- Phase 1 semantic contract.
- Phase 3 sequence archive and manifest, including the semantic-state summary.
- Corrected Phase 4 presentation, teaching frames, and teaching manifest.
- Local runtime/model inventory and caller output constraints.

Phase 3 masks are geometry authority. Corrected Phase 4 copy, role bindings, stage boundaries, and overlay pixels are presentation authority.

## Required plan

- Bind every important visual role to exactly one treatment type: `local_generated_material`, `deterministic_shader`, `fixed_semantic_color`, or `copied_overlay`.
- Declare at least one real local-generation job, fixed prompts, negative prompts, seeds, model family/root/inventory, parameters, protected regions, writable masks, keyframes, and baseline/candidate configurations.
- Use generated prompts only for bounded material swatches. Forbid text, diagrams, cracks, tunnels, waterways, objects, and compositional structure.
- Keep water/path dynamics deterministic. Generated material must never define topology, state, timing, or causal change.
- Freeze the complete plan before execution; allow no post-inspection resampling.
- For the retained karst case, choose exactly four semantic-milestone keyframes, one local model family, no more than two material classes, two candidates per class, and four generated images total.
- Preserve an 880×600 output, the full mechanism viewport, and exact restoration of the corrected Phase 4 overlay.

Return only the JSON plan. Do not claim execution, review, human approval, or Phase 6 readiness.
