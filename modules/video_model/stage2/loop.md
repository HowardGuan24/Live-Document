## 1. 最终目标

建立一条可复现、可评估、可逐步改进的通用流水线：

```text
概念说明
→ 分解成因果片段
→ 程序计算状态并生成解释动画
→ 按机制条件选择关键帧
→ 把程序数据转换成可解释的模型控制
→ 图像模型提升材质与光照
→ 保留程序决定的事实与几何
→ 视频模型生成相邻关键帧过渡
→ 自动检查、人工审图、报告和回归测试
```

Loop Engineer 的任务不是为每个概念手工修一组图，而是每轮提出一个可以被证伪的
通用假设，用固定输入做对照实验；有效改进只有在多个案例上通过回归后，才能进入通用
核心。

“可复现”在这里分成两层：

1. 程序状态、语义层、控制图、组合结果和报告必须在相同输入下逐文件一致；
2. 扩散模型在相同权重、软件、硬件、参数和种子下应可重跑。跨硬件可能不是逐像素
   相同，因此还要通过机制和视觉阈值，不能只比较文件哈希。

探索模式可以用固定种子组了解模型的成功率；正式生产模式必须冻结模型、配置、种子和
选择规则。同一输入不能每次由人从新候选里随意挑一张。如果最终仍需一次人工审美选择，
应把选中的候选 ID 和理由写入版本配置，重跑时只复现该已冻结结果。

## 2. 不把哪些事情混在一起

整个系统必须明确四种职责。

| 部分 | 负责决定 | 不负责决定 |
|---|---|---|
| 概念规划器 | 教学目标、因果片段、每段唯一主要变化 | 像素纹理和随机种子 |
| 程序动画 | 状态、位置、数量、拓扑、运动方向、教学标记 | 写实材质 |
| 图像模型 | 材料质感、自然纹理、局部光照和视觉丰富度 | 改写机制事实 |
| 视频模型 | 两个正确状态之间的连续外观和运动 | 推理缺失的中间机制 |

一个漂亮但机制错误的图不能晋级；一个机制正确但仍像程序塑料图的结果也不能宣称
图像增强成功。这两个维度要分别评分。

## 3. 跨学科基准套件（10 个新案例 + 1 个历史案例）

### 3.1 已有基准：三角洲

用户指定的视觉参考是：

```text
modules/video_model/stage1/output/keyframe_render/report.html
```

其中 `final/first.png`、`final/last.png` 和 `final/comparison.jpg` 用来建立 Stage 1
的材质、镜头稳定性和机制可读性基线。后续五帧序列及其通用框架证据位于：

```text
modules/video_model/stage1/output/keyframe_render/delta_sequence/report.html
```

Stage 1 不是不可超越的“标准答案”。当前报告已经说明，最终泥沙、水下沉积和湿沙有
较多确定性合成成分，SDXL 原始全图候选会让场景漂移。Stage 2 应把它当成最低基线和
回归案例：既不能丢掉它已经做到的机制一致性，也要验证图像模型是否真的带来更多自然
材质。

不同概念之间禁止用像素相似度或 CLIP 相似度直接比较。参考图只用于同一套人工量表：
镜头是否稳定、材料是否自然、机制是否一眼可读、是否出现模型伪影。

### 3.2 Stage 2 新案例集

`modules/video_model/stage2/case.txt` 定义数学、物理、化学、生物、地理各两个新案例：

| 学科 | 案例 | 主要能力覆盖 |
|---|---|---|
| 数学 | 单位圆生成正弦；勾股定理拼图证明 | 精确几何、同步轨迹、对象身份、刚体运动 |
| 物理 | 双源水波干涉；电磁感应 | 高度/法线、周期相位、矢量场、状态符号反转 |
| 化学 | 酸碱滴定；蒸发结晶 | 连续浓度、透明混合、阈值、成核与质量守恒 |
| 生物 | 有丝分裂；气孔开闭 | 多对象身份、形变、分裂拓扑与隐变量 |
| 地理 | 牛轭湖形成；地形雨 | 边界演化、水体拓扑、地形、气流和耦合标量场 |

水面波不再是唯一的新基准，而是连续高度场路线的一个代表。十个案例共同检验框架是否
能按数据类型选择控制方式，而不是把三角洲插件换几个名词继续使用。

### 3.3 分层回归，避免每轮盲目跑十套模型

回归分为四层：

1. **契约冒烟层**：十个案例都运行 schema、状态、语义层、控制图和报告链接检查，
   不加载生成模型；
2. **路线回归层**：每轮运行当前案例、至少两个共享相关数据类型但来自其他学科的案例，
   再运行三角洲；用于判断一次策略是否可能通用；
3. **学科代表层**：每个学科冻结一个代表案例，共五个，用于阶段版本的图片回归；
4. **完整发布层**：正式通用版本对十个案例运行全部已实现的关键帧检查；视频按刚体
   运动、连续场传播、液体混合、对象分裂和地形拓扑五类运动分别保留代表回归。

只在一个案例有效的策略保留在该案例的配置或插件中。没有通过路线回归层的策略不能
进入通用核心；没有通过学科代表层和契约冒烟层的版本不能发布。

## 4. 程序动画必须交付的标准输入

为了让同样的程序图可以重复处理，生成动画时就要输出机器可读信息，避免事后从截图
猜回机制。

每个案例至少提供：

```text
case/
├── concept_spec.json       # 教学目标、片段顺序、术语和禁区
├── sequence_spec.json      # 关键帧、相邻变化、固定内容和模型配置
├── states.jsonl            # 每个时刻的原始程序状态
├── timeline.json           # 展示帧与程序状态的对应关系
├── program_frames/         # 带教学标记、供人查看的程序图
└── model_inputs/
    ├── clean_frames/       # 去掉 UI、标题、图例后的视觉底图
    ├── layers/             # 由状态直接导出的语义层
    └── geometry/           # 可选的硬边界、深度、法线等控制
```

如果用户只能提供几张固定程序图，也允许使用 `image_only` 导入模式，但必须先生成并
冻结一份人工可审查的帧规格，明确每张图的事实、允许变化区域和固定区域。后续 loop
不能一边优化结果一边偷偷修改这些标注。

### 4.1 每个语义层的统一声明

语义层不能只叫 `mask_1` 或 `conditioning`。每一层都要记录：

- 稳定 ID；
- 普通话名称和一句话含义；
- 来源状态字段及推导方法；
- 数据类型与取值范围；
- 坐标系和投影方法；
- 是否真实输入模型；
- 在最终图中控制什么；
- 是否允许出现在教学叠加层中。

通用层类型如下：

| 类型 | 例子 | 默认处理原则 |
|---|---|---|
| `hard_boundary` | 岸线、物体轮廓、容器边界 | 可生成稀疏 Canny；程序保留拓扑 |
| `region` | 新出现物体、允许修改区域 | 用于局部生成或受限组合 |
| `scalar_field` | 浓度、温度、厚度、振幅 | 保留连续数值，不能强行变成密集线稿 |
| `vector_field` | 流向、速度、受力方向 | 用于程序运动或视频审计，箭头不默认进入成品 |
| `height_or_normal` | 地形、水面高度和法线 | 程序决定大形状，模型只增加材质 |
| `object_identity` | 粒子、细胞、振源 | 记录数量、位置、身份和跨帧对应 |
| `annotation` | 文字、箭头、图例和高亮 | 写实化之后由程序叠加，不交给模型写字 |

框架允许某个案例没有 Canny、没有粒子或没有深度；不允许为凑接口伪造不存在的数据。

## 5. 通用框架与案例插件的边界

### 5.1 通用核心

换概念时不应修改：

- schema 校验与标准目录；
- 输入、代码、模型、提示词和图片的哈希记录；
- 关键帧选择接口；
- 控制路线选择器；
- 提示词编译、token 检查和负向禁区；
- 固定种子实验矩阵与缓存；
- 确定性的候选排序、已审核选择冻结和生产模式复现；
- 原始模型输出、程序约束结果和最终交付的分离；
- 通用评分、盲评联系表、回归测试；
- 首尾帧视频交接格式；
- HTML 报告生成与链接完整性检查。

### 5.2 案例插件和配置

换概念时允许替换：

- 如何读取该程序的状态；
- 如何把状态投影到画布；
- 本案例有哪些语义层；
- 每帧的具体外观语言；
- 数量、单调性、连通性、守恒关系等案例验收；
- 教学叠加层的内容。

“湿沙应该更深”“波纹必须有两个振源”都属于案例事实或案例视觉配置；“新出现的材料
必须与邻域达到最低可读性”“模型不能改变程序给出的对象数量”才可以成为通用规则。

### 5.3 通用改进的晋级条件

一次实验得出有效结论后，先写成候选策略。只有同时满足以下条件才进入核心：

1. 没有在代码里出现案例名称、固定帧号或案例专用状态字段；
2. 当前案例的硬门禁全部通过；
3. 至少两个其他学科、且共享相关数据类型的路线回归案例通过；
4. 三角洲历史回归硬门禁通过；
5. 路线回归集的总分均未下降超过 2 分，目标维度至少一个案例提升 5 分；
6. 十个案例的无需模型契约冒烟测试全部通过；
7. 固定种子组的大多数候选均改善，而不是只挑中一个幸运种子；
8. 报告能够显示改动前后、参数差异、失败候选和评分证据。

满足上述条件可以把策略标记为通用核心候选。阶段版本发布前还必须通过五个学科代表
案例；否则结果可以作为案例成果保存，但不得宣传为已发布的通用框架进步。

## 6. 一轮 Loop 的固定步骤

每一轮只验证一个主要假设，防止同时改提示词、控制图、合成权重和种子后无法判断原因。

### Step 1：冻结输入和基线

- 记录输入图、状态、代码、模型权重和配置哈希；
- 记录本轮使用的关键帧和固定种子组；
- 从缓存重建当前最佳结果；
- 生成带标签和盲评两种对比表。

在同一实验中不得更换程序状态、裁图、镜头或参考答案。确实需要改输入时，要创建新的
基准版本，不能覆盖旧版本。

### Step 2：从证据写一个通用假设

假设必须包含：

```text
观察到的问题：
可能原因：
本轮唯一改动：
适用的通用数据类型：
预期改善的评分项：
什么结果会证伪它：
需要回归的案例：
最多运行多少候选和视频：
```

合格示例：“连续高度场变成密集 Canny 后出现刻痕；对
`height_or_normal` 默认关闭详细 Canny，并由程序法线保留大尺度明暗，应该提高水面
材质自然度，同时不降低节点拓扑得分。”

不合格示例：“把波纹 prompt 再写好一点。”它既没有明确原因，也无法推广。

### Step 3：先做低成本控制实验

按由低到高的成本顺序：

1. 验证程序状态、语义层和投影，不加载模型；
2. 只在一张代表帧上跑少量固定种子；
3. 硬门禁通过后，再跑全部关键帧；
4. 关键帧稳定后，才生成相邻首尾帧视频。

每轮至少保留一个当前最佳基线和一个单变量实验。可按问题增加负对照，例如详细 Canny
与稀疏 Canny，但不能只保存好看的结果。

### Step 4：保存原始证据

以下内容不可覆盖：

- 模型直接输出的 raw candidate；
- 模型实际看到的每张控制图；
- 完整正向与负向提示词及 token 数；
- 模型 ID、权重指纹、精度、采样器、步数、强度和种子；
- 生成耗时、缓存命中、输入签名；
- 程序约束后的 composite；
- 最终选择及选择理由；
- 失败结果和被拒绝原因。

`raw`、`composite` 和 `final` 必须是三个明确分类。程序合成图不能冒充模型原图。

### Step 5：先过硬门禁，再评分

任何硬门禁失败，本轮直接拒绝，不用“画面更好看”抵消：

- 尺寸、色彩模式、文件和 manifest 对应；
- 程序指定的对象数量、身份、位置范围和拓扑；
- 相邻状态的因果顺序；
- 固定镜头与静态区域不发生超阈值漂移；
- UI、图例、箭头、文字和水印不泄漏进写实底图；
- raw 与 composite 分开；
- 提示词没有被 tokenizer 静默截断；
- 模型和运行时没有静默替换；
- 视频首尾与输入关键帧对应，且没有换场。

通过硬门禁后，再计算第 7 节的质量分。

### Step 6：运行跨案例回归

先在当前案例验证目标改进，再根据本轮涉及的语义层类型，从覆盖矩阵选择至少两个其他
学科案例，并运行三角洲历史回归。回归输入、种子、评分版本不变。案例专用插件可以
不同，但通用路线选择、记录、评分和报告程序必须相同。

### Step 7：接受、保留为案例策略或拒绝

- `promote_to_core`：满足第 5.3 节全部条件；
- `keep_case_specific`：当前案例有效，但没有跨案例证据；
- `reject`：硬门禁失败、平均质量退化或结论依赖挑种子；
- `inconclusive`：样本不足或指标不能区分，需要先改评估方法。

结论和证据写入实验账本。被拒绝实验不能删除，因为它定义了模型能力边界。

### Step 8：有阶段成果时生成报告

只有接受了新策略、完成了新案例里程碑或明确确认一个能力边界，才发布新的阶段报告。
普通失败尝试进入实验账本，并在下一份阶段报告中归纳，避免为每个种子制造一份报告。

## 7. 统一评分方法

### 7.1 图片与序列：100 分

| 维度 | 分值 | 核心问题 |
|---|---:|---|
| 机制忠实度 | 25 | 程序定义的位置、数量、范围、拓扑和先后关系是否正确 |
| 跨帧一致性 | 20 | 镜头、背景、固定物体、材质尺度和光照是否稳定 |
| 材质提升 | 15 | 与程序底图相比是否更像真实材料，而不是塑料、贴图或刻痕 |
| 教学可读性 | 15 | 不看内部变量时，目标变化是否仍能被第一次观看者指出 |
| 伪影控制 | 10 | 是否没有多余物体、文字、硬描边、结构融化和重复纹理 |
| 种子稳健性 | 10 | 固定种子组中是否多数有效，而不是只有一张幸运图 |
| 可复现与可审计 | 5 | 参数、哈希、中间图和选择依据是否齐全 |

硬门禁通过是评分前提。每个分项都必须保存数值、普通话判断和对应图片，不能只给一个
总分。

Stage 1 参考图的比较采用成对盲评：

- 哪一组材料更自然；
- 哪一组固定场景更稳定；
- 哪一组机制变化更清楚；
- 哪一组模型伪影更少。

这里比较的是质量维度，不比较“三角洲是否长得像波纹”。

### 7.2 视频附加评分：100 分

| 维度 | 分值 | 核心问题 |
|---|---:|---|
| 首尾遵守 | 20 | 第一帧和最后一帧是否忠实于输入 |
| 中间机制 | 25 | 中间运动是否沿程序允许的路径推进 |
| 时间连续性 | 20 | 是否无闪烁、跳变、倒退和突然出现 |
| 场景稳定性 | 15 | 镜头、背景和固定物体是否不漂移 |
| 运动自然度 | 10 | 速度和形变是否可信 |
| 教学可读性 | 10 | 过渡是否帮助理解，而不是只做视觉变形 |

视频需从程序状态定义可测的案例审计，例如泥沙前缘单调下游、波前总体向外传播。
这些审计属于案例插件；首尾误差、闪烁、静态漂移和文件完整性属于通用核心。

### 7.3 自动指标不能替代审图

梯度、颜色距离、边缘重合、光流、PSNR 和图像相似度用于发现异常，不自动选择
“最好看”的候选。盲评图中不显示 seed、策略名或内部代号，评审后再解盲。

## 8. 控制路线的通用选择规则

Loop Engineer 按数据类型选择最小必要控制，不默认所有案例都走 Canny。

1. **有明确硬边界**：稀疏 Canny 或区域边界可以约束几何。
2. **软浓度或连续标量**：程序直接渲染连续层，提示词只描述材质；不得把每个等值线
   都交给 Canny。
3. **高度或法线场**：程序先决定大尺度形状与受光方向，图像模型提供材质残差或局部
   重绘。
4. **需要精确数量或身份的物体**：程序保留实例 ID，模型只能在实例允许区域内改外观。
5. **只有外观变化、没有几何变化**：优先局部材质增强，不重新生成全图。
6. **没有合适控制模型**：明确记录 `control=off`，保存失败边界；不得静默换成另一个
   未审核模型。
7. **文字和教学标记**：写实底图完成后由程序叠加。

提示词只表达镜头、材料、光照、整体风格、本帧主要变化和禁区。坐标、数量、拓扑和
精确范围不能只靠语言保证。

## 9. 提示词优化规则

提示词分为五个可追踪部分：

```text
scene_identity      固定场景和镜头
material_goal       希望模型改善的材料与光照
state_delta         本帧唯一主要变化的自然语言
must_preserve       不得变化的内容
negative_artifacts  常见模型错误和本阶段禁区
```

案例中的具体名词放在 `sequence_spec`，编译顺序和 token 检查放在核心。每轮只修改一个
提示词部分；同一对照保持模型参数、控制图和种子不变。若语言无法稳定控制精确位置，
结论应是增加程序约束或改变生成路线，而不是无限堆叠形容词。

## 10. 分阶段实施计划

### Phase 0：冻结基线与评分协议

- 固定 Stage 1 两套参考结果和输入哈希；
- 为十个新案例分配稳定 ID、能力标签、讲解目标和禁区；
- 冻结五个学科代表案例及路线回归的选择规则；
- 实现评分 schema、实验账本和报告目录规则；
- 不生成模型图。

成果：`phase-0-report.html`，解释案例集为什么这样组成、如何选择回归集、哪些分数需要
人工判断。

### Phase 1：通用契约与无需模型的骨架

- 实现统一 `concept_spec`、`sequence_spec`、状态和语义层 schema；
- 实现硬边界、区域、标量场、矢量场、高度/法线、对象身份和教学叠加层接口；
- 为十个案例建立最小有效 fixture，运行契约冒烟；
- 验证同一输入的控制图、manifest 和报告逐文件可重复。

成果：框架骨架、十案例契约结果和 `phase-1-report.html`。这一阶段不声称已经完成任何
写实关键帧。

### Phase 2：五学科哨兵案例的确定性程序动画

- 数学：优先勾股拼图，验证精确几何、对象身份和刚体变换；
- 物理：优先水波干涉，验证连续高度场和相位；
- 化学：优先酸碱滴定，验证透明液体和局部浓度场；
- 生物：优先有丝分裂，验证多对象身份和分裂拓扑；
- 地理：优先地形雨，验证固定地形、矢量场和耦合标量场；
- 每个案例按机制条件选择关键帧并导出教学叠加层。

成果：五套可复现程序动画、关键帧规格和 `phase-2-report.html`。报告逐案例解释程序状态
如何变成可视图层。

### Phase 3：按数据类型探索图像模型能力边界

在五个哨兵案例的代表帧上做单变量矩阵，路线由数据类型决定，例如：

- 自由生成；
- 稀疏硬边界；
- 对连续场使用详细 Canny 的负对照；
- 程序区域或高度/法线保形加材质增强；
- 对精确对象使用实例允许区域；
- 必要时再测试局部重绘或其他已明确登记的控制模型。

成果：确定哪些信息适合交给图像模型、哪些必须由程序保留。发布
`phase-3-report.html`，包括所有原始候选、跨学科对照和失败证据。

### Phase 4：扩展到剩余五个案例并稳定关键帧

- 为单位圆、电磁感应、蒸发结晶、气孔开闭和牛轭湖补齐确定性程序与案例插件；
- 按 Phase 3 接受的数据类型路线生成十案例关键帧；
- 优化跨帧场景一致性和材料自然度；
- 运行固定种子稳健性、五学科代表集、三角洲回归和盲评；
- 形成视频交接规格。

成果：十案例关键帧状态表、已完成案例的最终序列、跨案例回归和
`phase-4-report.html`。某个案例没有达到门禁时必须明确标为未完成，不能用平均分掩盖。

### Phase 5：按运动类型生成首尾帧视频

- 每个视频只连接相邻机制状态；
- 固定首尾、提示词、种子和时长；
- 检查端点误差、闪烁、场景漂移和案例运动方向；
- 至少覆盖刚体运动、连续场传播、液体混合、对象分裂和地形拓扑变化；
- 失败时回到关键帧拆分或视频控制，不让视频模型补做概念规划。

成果：各类代表视频、采样帧、工作流文件、评分和 `phase-5-report.html`。

### Phase 6：通用框架晋级

状态：**已通过（v0.1.0）**。

- 清理案例硬编码；
- 十个新案例运行契约冒烟和所有已实现的关键帧门禁；
- 五学科代表集及三角洲用相同核心完成正式图片回归；
- 五类运动代表完成视频回归；
- 记录哪些策略进入核心、哪些仍留在插件；
- 固定版本号、变更记录和从零复现命令。

成果：可复用版本与 `stage2-final-report.html`。只有此阶段通过，才称为“通用框架
版本”，此前均称为候选方案。

实际发布结果：

- 十个案例的合同 fixture、490 帧程序和 40 张关键帧全部通过；
- 五学科代表图片全部通过；数学与物理复核冻结代表帧，化学、生物、地理对四帧
  序列运行统一的多供体材质残差核心；
- 五类运动全部通过，其中刚体运动与液体混合明确使用程序回退；
- Stage 1 三角洲 14 个冻结证据文件逐一复核 SHA-256，未被覆盖；
- 八次 LTX 模型视频正负提示词使用实际 Gemma tokenizer 审计，无静默截断；
- 发布核心 Python 文件不包含十个基准案例 ID；对象数量、方程、颜色、阈值、
  提示词和 evaluator 参数留在插件或 JSON 配置；
- Phase 6 新增“材质增强不得是原图复制”硬门，修复 CHEM-01 首轮机器门假通过。

## 11. 每份阶段报告必须让新人看懂

HTML 报告按实际生成顺序组织，至少包含：

1. 这阶段要解决什么，用日常语言解释概念；
2. 输入的程序图和选择这些状态的原因；
3. 程序状态如何变成每个语义层；
4. Canny、深度、法线或其他控制图如何得到，以及是否真的输入模型；
5. 完整提示词如何由五部分拼接；
6. 模型、参数、精度、种子和权重指纹；
7. 所有 raw candidates 的带标签表与盲评表；
8. raw、composite、final 的并排对比；
9. 自动硬门禁、分项评分和人工判断；
10. 本轮失败了什么、为什么失败；
11. 从案例得到的通用认识及其跨案例证据；
12. 从零复现命令、输入输出哈希和缓存说明；
13. 下一阶段只准备验证哪一个问题。

页面中不能只出现 `mask`、`conditioning`、`seed 3102` 之类内部词。第一次出现时必须
解释它是什么、从哪里来、影响哪一步。关键中间图直接显示在页面里，不只给文件链接。

## 13. 自主运行的预算、停止与人工检查点

Loop 必须有预算，不能因为“自我迭代”无限消耗模型时间。默认每轮预算写进假设文件：

- 一个主要假设；
- 先一张代表帧；
- 每种配置使用同一小组固定种子；
- 通过图片门禁后最多进行两次视频试验；
- 达到预算仍无结论时标记 `inconclusive`，不偷偷扩大搜索。

出现以下任一情况立即停止当前轮：

- 机制硬门禁失败；
- 模型或运行时与登记版本不符；
- 输入基准发生未解释变化；
- 连续三轮在目标分项提升不足 2 分；
- 改进依赖单一幸运种子；
- 需要下载、替换模型或改变教学目标；
- 需要用户在两种教学表达之间作选择。

Phase 自动晋级规则：

1. 每个 Phase 结束时由 Agent 按该阶段硬门禁、分项评分、确定性重建和报告完整性自评；
2. 全部硬门禁通过且达到阶段阈值时，自动把 manifest 标为 `passed` 并进入下一 Phase；
3. 未通过时，保持在当前 Phase，写入失败证据并继续做单变量优化，不向用户索要普通
   技术判断；
4. 只有教学目标存在互斥选择、需要下载或替换模型、需要新的外部权限，或连续失败达到
   本节停止阈值时才暂停并报告；
5. Phase 6 的发布判断也由同一套冻结协议完成，不把常规验收转交给用户。

## 14. Loop Engineer 的决策伪代码

```text
load_frozen_benchmarks()
rebuild_current_best_from_manifests()

while phase_budget_remains:
    problem = inspect_scores_and_visual_evidence()
    hypothesis = write_one_general_falsifiable_hypothesis(problem)
    run_deterministic_checks(hypothesis)

    if deterministic_gate_failed:
        record_rejection()
        continue

    run_small_fixed_seed_experiment()
    keep_raw_outputs()

    if mechanism_gate_failed:
        record_rejection()
        continue

    score_without_strategy_labels()
    select_regressions_by_semantic_layer_and_discipline()
    run_route_regression_plus_delta()
    classify_as_core_case_specific_reject_or_inconclusive()
    update_experiment_ledger()

    if phase_has_accepted_result:
        build_beginner_readable_report()

self_evaluate_phase()
advance_if_passed_else_continue_single_variable_optimization()
```

这个循环优化的是“框架中的一个可验证判断”，不是自动挑一张最漂亮的图。最终成功
标准是：固定输入可复现、机制事实不丢、图像模型确实提升材料质感、视频只补连续运动，
而且同一核心通过十案例契约、五学科图片代表集、五类运动代表和三角洲历史回归。
